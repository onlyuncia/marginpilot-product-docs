# Use Cases MarginPilot

Документ описывает три сценария работы менеджера с SKU: изменение цены, управление участием в акции и анализ экономики после продаж. В каждом сценарии отдельно показаны действие пользователя, ответ Ozon и проверка фактического результата.

## UC-001. Подготовка и применение пакета цен в Ozon

**Цель:** изменить цены выбранных SKU и проверить, что Ozon применил отправленные значения.

**User Story:** как менеджер кабинета Ozon, я хочу подготовить пакет новых цен, увидеть позиции ниже экономического порога и проверить применение изменений, чтобы контролировать результат отправки.

**Основной участник:** менеджер кабинета Ozon.

**Система в границах UC:** MarginPilot.

**Внешние системы:** 1С — предоставляет данные для расчёта; Ozon — принимает изменения и возвращает актуальные цены.

**Триггер:** менеджер открывает экран оценки экономики SKU, чтобы подготовить пакет цен.

**Предусловия:** менеджер авторизован в MarginPilot; обмен с 1С и Ozon настроен.

### Основной сценарий

Основной сценарий описывает пакет, в котором все выбранные цены не ниже экономического порога.

1. MarginPilot показывает список SKU и расчётную экономику продажи при предлагаемых ценах.
2. Менеджер задаёт новые цены и выбирает хотя бы один SKU. После выбора кнопка «Загрузить цены» становится доступной.
3. Менеджер нажимает «Загрузить цены».
4. MarginPilot сравнивает предложенную цену каждого выбранного SKU с его экономическим порогом.
5. Если цен ниже порога нет, MarginPilot формирует пакет из выбранных SKU. Дополнительного подтверждения не требуется.
6. MarginPilot отправляет подготовленный пакет в Ozon через API.
7. MarginPilot разбирает ответ Ozon по каждому SKU: `updated` показывает результат обновления, а `errors` — причину отказа, если она есть.
8. MarginPilot автоматически получает актуальные цены из Ozon и сверяет их с отправленными. Менеджеру не нужно запускать сверку вручную.
9. На странице результата интерфейс автоматически обновляет состояние пакета. Менеджер проверяет итог по SKU.

Страницу результата можно открыть сразу после принятия пакета, не дожидаясь завершения отправки и сверки.

**Успешное постусловие:** все цены из отправленного пакета применены в Ozon и сверены с отправленными значениями.

### Альтернативные сценарии

| Ветка | Точка входа | Действия и результат |
| --- | --- | --- |
| А1. SKU не выбраны на основном экране | Шаг 2 | Кнопка «Загрузить цены» недоступна. Отправка не начинается. |
| А2. Есть цены ниже порога | Шаг 4 | MarginPilot открывает панель только с такими SKU. Их чекбоксы пустые по умолчанию. Менеджер может отметить позиции, которые хочет включить в отправку. |
| А2.1. Подтверждён непустой пакет | А2 | Менеджер нажимает «Подтвердить». В пакет входят SKU с допустимой ценой и вручную отмеченные SKU ниже порога. MarginPilot сохраняет автора пакета и отдельно фиксирует включение позиций ниже порога, затем продолжает с шага 6. |
| А2.2. Отмена | А2 | Менеджер нажимает «Отмена». Панель закрывается, ни одна цена не отправляется. |
| А2.3. Итоговый пакет пуст | А2 | Если в пакете были только SKU ниже порога и менеджер не отметил ни один из них, нажатие «Подтвердить» показывает toast-уведомление «SKU не выбраны». Запрос в Ozon не отправляется. |

| А4. Ozon API недоступен | Шаг 6 | MarginPilot показывает менеджеру toast-уведомление о недоступности Ozon API. Применение цен не считается подтверждённым. |
| А5. Таймаут ответа Ozon | Шаг 7 | MarginPilot сохраняет состав пакета со статусом «Результат отправки не подтверждён» и показывает toast-уведомление менеджеру. Система считывает актуальные цены по SKU и показывает совпадения, расхождения и позиции, которые пока не удалось проверить. Для непроверенных SKU чтение повторяется позже. Пакет не отправляется повторно автоматически. |

**Toast при таймауте (А5):** заголовок «Нет ответа от Ozon»; сообщение «Пока неизвестно, применились ли цены. Проверяем пакет по SKU. Не отправляйте его повторно до завершения проверки.»

**Результат без отправки:** при А1, А2.2 и А2.3 MarginPilot не передаёт новые цены в Ozon.

## UC-002. Управление участием SKU в акции Ozon

**Цель:** оценить экономику участия товара в акции, передать решение в Ozon и проверить фактический статус каждого выбранного товара.

**User Story:** как менеджер кабинета Ozon, я хочу видеть, какие товары можно добавить в акцию, а какие стоит вывести из неё, чтобы принимать решения с учётом экономики продажи и проверять их исполнение.

**Основной участник:** менеджер кабинета Ozon.

**Система в границах UC:** MarginPilot.

**Внешние системы:** 1С — предоставляет данные для расчёта; Ozon — принимает решение об участии товара в акции и возвращает актуальный статус.

**Триггер:** менеджер открывает экран оценки экономики SKU, чтобы пересмотреть участие товаров в акции.

**Предусловия:** менеджер авторизован в MarginPilot; обмен с 1С и Ozon настроен.

### Основной сценарий

Основной сценарий описывает действие с одним или несколькими SKU, для которых Ozon подтвердил целевой статус участия в акции.

1. MarginPilot показывает товары, их текущие цены и расчётную экономику участия в акции. Для каждого SKU менеджер видит, подходит ли он для акции, доступный уровень бустинга и причины рекомендации выйти из акции — цену ниже экономического порога или нулевую прогнозную прибыль с продажи.
2. Менеджер выбирает действие — «Добавить в акцию» или «Удалить из акции» — и отмечает хотя бы один SKU. Для входа в акцию он указывает отдельную цену акции; прежняя цена отображается как старая, зачёркнутая. После выбора SKU кнопка соответствующего действия становится доступной.
3. Менеджер нажимает кнопку выбранного действия.
4. При входе в акцию MarginPilot сравнивает цену акции каждого выбранного SKU с его экономическим порогом. При выходе из акции эта проверка не требуется.
5. MarginPilot формирует пакет, проверяет, что по выбранным товарам нет незавершённой отправки того же действия, и передаёт его в Ozon через API. Если цена входа ниже порога, этому шагу предшествует подтверждение менеджера по ветке А2.1; в остальных случаях дополнительное подтверждение не требуется.
6. MarginPilot разбирает ответ Ozon: `result.product_ids` содержит идентификаторы товаров, добавленных в акцию или удалённых из неё; `result.rejected` — товары, для которых действие отклонено, и причины отказа. Система сопоставляет возвращённые `product_id` с товарами в интерфейсе.
7. MarginPilot автоматически получает из Ozon актуальный статус участия выбранных товаров и сверяет его с запрошенным действием. Менеджеру не нужно запускать сверку вручную.
8. На странице результата интерфейс автоматически обновляет состояние пакета. Менеджер видит итог по каждому товару: целевой статус подтверждён, действие не выполнено или результат пока не удалось проверить.

Страницу результата можно открыть сразу после принятия пакета, не дожидаясь завершения отправки и сверки.

**Успешное постусловие:** все товары из отправленного пакета получили целевой статус участия в акции, и MarginPilot подтвердил это сверкой с Ozon.

При выходе товара из акции прежнюю цену восстанавливает Ozon. MarginPilot не отправляет для этого отдельный запрос на изменение цены.

### Альтернативные сценарии

| Ветка | Точка входа | Действия и результат |
| --- | --- | --- |
| А1. SKU не выбраны | Шаг 2 | Кнопки добавления и удаления из акции недоступны. Отправка не начинается. |
| А2. Цена входа ниже порога | Шаг 4 | MarginPilot открывает панель предупреждения только с такими SKU. Их чекбоксы пустые по умолчанию; менеджер может вручную отметить позиции, которые всё же хочет добавить в акцию. На выход из акции эта ветка не распространяется. |
| А2.1. Подтверждён непустой пакет | А2 | Менеджер нажимает «Подтвердить». В пакет входят SKU с допустимой ценой входа и вручную отмеченные SKU ниже порога. MarginPilot сохраняет автора пакета и отдельно фиксирует включение позиций ниже порога, затем продолжает с шага 5. |
| А2.2. Отмена | А2 | Менеджер нажимает «Отмена». Панель закрывается; ни один товар из текущего пакета не передаётся в Ozon. |
| А2.3. Итоговый пакет пуст | А2 | Если были выбраны только SKU с ценой входа ниже порога и менеджер не отметил ни один из них, нажатие «Подтвердить» показывает toast «SKU не выбраны». Запрос в Ozon не отправляется. |
| А3. Часть товаров отклонена или целевой статус не подтвердился | Шаги 6–7 | MarginPilot показывает отклонённые позиции и причины из `result.rejected`, а также расхождения, выявленные при автоматической сверке. Результат всего пакета не считается успешным. |
| А4. Ozon API недоступен | Шаг 5 | MarginPilot показывает уведомление о недоступности Ozon API. Изменение участия не считается подтверждённым. |
| А5. Таймаут ответа Ozon | Шаг 6 | Результат отправки неизвестен. MarginPilot показывает уведомление и автоматически запрашивает актуальный статус выбранных товаров в Ozon. По итогам сверки он показывает подтверждённые изменения, расхождения и товары, которые пока не удалось проверить. Пока результат не выяснен, повторная отправка того же действия по этим товарам не выполняется. Таймаут сам по себе не означает, что действие не выполнено. |
| А6. Актуальный статус получить не удалось | Шаг 7 или А5 | MarginPilot показывает, для каких товаров результат остался неподтверждённым, и повторяет чтение статуса позже. Ответ на отправку, если он был получен, и фактический статус участия не смешиваются в один результат. |
| А7. Повторное действие до выяснения результата | Шаги 3–5 или А5 | Если менеджер повторяет действие по товару и акции, для которых отправка ещё не завершена или её результат не подтверждён, MarginPilot не создаёт второй запрос в Ozon по этой позиции. Повторное действие возможно после установления результата, если целевой статус товара не достигнут. |

**Toast при таймауте (А5):**

- Добавление в акцию — заголовок «Нет ответа от Ozon»; текст «Проверяем, добавлены ли выбранные товары в акцию. Пока результат не выяснен, повторный запрос не отправляется.»
- Удаление из акции — заголовок «Нет ответа от Ozon»; текст «Проверяем, удалены ли выбранные товары из акции. Пока результат не выяснен, повторный запрос не отправляется.»

**Результат без отправки:** при А1, А2.2 и А2.3 MarginPilot не передаёт действие в Ozon.

## UC-003. Анализ плановой и фактической экономики SKU

**Цель:** увидеть отклонение фактической экономики SKU от плана и учесть его при следующем ценовом решении.

**User Story:** как менеджер кабинета Ozon, я хочу видеть плановую и фактическую экономику SKU за выбранный период и отклонение между ними, чтобы учитывать результат при следующем ценовом решении.

**Основной участник:** менеджер кабинета Ozon.

**Система в границах UC:** MarginPilot.

**Внешние системы:** 1С и Ozon — источники данных, сохранённых для анализа в MarginPilot.

**Триггер:** менеджер открывает экран оценки экономики SKU, чтобы проанализировать результат продаж.

**Предусловия:** менеджер авторизован в MarginPilot; данные о продажах и расходах загружены. Для полного сравнения нужна версия плана, действовавшая на момент каждой продажи.

### Основной сценарий

Основной сценарий описывает SKU, у которого были продажи за выбранный период.

1. Менеджер выбирает SKU и период.
2. MarginPilot получает данные о продажах и фактических расходах за период и находит сохранённые версии планового расчёта SKU.
3. Для каждой проданной единицы система определяет версию плана, действовавшую на момент продажи. MarginPilot суммирует плановые результаты по фактически проданному количеству и отдельно рассчитывает фактический результат за период, включая рекламные расходы.
4. MarginPilot показывает план, факт и отклонение: в сумме по SKU и в пересчёте на проданную единицу.
5. Менеджер просматривает результат.

**Успешное постусловие:** план, факт и отклонение по выбранному SKU и периоду рассчитаны и показаны менеджеру. Следующее ценовое решение не входит в этот UC.

### Альтернативный сценарий

| Ветка | Точка входа | Действия и результат |
| --- | --- | --- |
| А1. Продаж за период не было | Шаг 3 | MarginPilot показывает фактические расходы по SKU за период, в том числе рекламные. Показатели на проданную единицу не рассчитываются: делить итог на нулевое количество продаж нельзя. |
| А2. Для продажи нет действовавшей версии плана | Шаг 3 | Плановый результат этой продажи остаётся неопределённым. MarginPilot не подставляет ноль и не берёт более позднюю версию. |

**Правило сравнения:** если за период менялись цена или участие в акции, прежний план не заменяется последним расчётом. Для каждой продажи используется версия плана, действовавшая в её момент; плановый итог за период складывается по всем таким продажам. Фактические рекламные списания учитываются за период отдельно от планового расхода на одну продажу.

**Правило отклонения:** отклонение в рублях рассчитывается как `факт − план`. Для прибыли положительное значение означает результат выше плана, отрицательное — ниже. Для расходов положительное значение означает перерасход, отрицательное — экономию. Отклонение на проданную единицу — разница между фактом на единицу и планом на единицу, взвешенным по фактически проданному количеству. При нулевых продажах этот показатель не рассчитывается.

**Связанные артефакты:** [БП-03. План-факт экономики SKU](02-PROCESS-AS-IS-TO-BE.md), [функциональные требования ФТ-22–ФТ-24](03-FUNCTIONAL-REQUIREMENTS.md).
