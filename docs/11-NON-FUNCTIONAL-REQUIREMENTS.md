# Нефункциональные требования к MarginPilot

Требования ниже разделены на выполненные в рабочей системе и целевые для её расширения.

## Рабочий контур

Рабочий профиль: три менеджера, два кабинета Ozon и около 3600 SKU. Двое менеджеров вели DBS, один — FBO; это распределение работы, не система ролей. Сценарии кейса относятся к DBS.

Полный цикл пересчёта, отправки и сверки цен занимал 10–20 минут при пакетах разного размера. Это наблюдение, а не норматив для каждого запуска.

## Подтверждённые требования

НФТ-01 и НФТ-02 проверяются при трёх одновременных сеансах и каталоге до 3600 SKU. Ожидание 1С и Ozon в указанные сроки не входит. По подтверждению участника проекта, НФТ-01–НФТ-03 выполнялись в эксплуатации.

| ID | Требование | Проверка |
| --- | --- | --- |
| НФТ-01 | Экран экономики готов к работе за ≤3 с (p95). | От открытия экрана до доступности элементов управления. |
| НФТ-02 | Расчёт экономики и порогов пакета занимает ≤60 с (p95). | От запуска расчёта до результата по всем SKU. |
| НФТ-03 | Вход и просмотр загруженных данных доступны ≥99,5% календарного месяца; сбои 1С и Ozon учитываются отдельно. | Проверки входа и открытия экрана SKU. |
| НФТ-04 | Ответ Ozon не заменяет сверку конечного состояния. Если проверить SKU не удалось, система повторяет чтение позже; действие по акции до выяснения результата не отправляется повторно. | Частичный ответ, таймаут, повторное нажатие, повторная сверка по SKU. |
| НФТ-05 | После подтверждённого изменения цены или акции создаётся новая версия плана; продажа относится к версии на момент продажи. | План-факт для продаж до и после изменения. |
| НФТ-06 | Подтверждённое решение отправить SKU ниже порога хранится один год с пользователем, временем, кабинетом Ozon и SKU. | Запись и срок хранения в журнале. |
| НФТ-07 | Доступ требует авторизации. Разделение DBS и FBO по правам не применяется. | Отказ без авторизации. |

## Целевые требования при расширении

Целевой профиль: до 4000 SKU и 50 одновременных пользователей. Чтение через внутренний API и отправка пакетов проверяются отдельно. Показатели ниже не относятся к достигнутым результатам внедрённой системы.

| ID | Требование | Проверка |
| --- | --- | --- |
| НФТ-08 | Чтение: 100 RPS — 15 минут без перегрузки; 200 RPS — 5 минут с явной обработкой отказов и восстановлением. Для 200 RPS норматив НФТ-09 не действует. | Стенд с 50 сеансами и 4000 SKU; ошибки, отклик, восстановление. |
| НФТ-09 | Внутренний API: чтение ≤200 мс (p95) при 100 RPS; приём команды на пакет ≤500 мс (p95) при 10 параллельных отправках. Применение в Ozon измеряется отдельно. | Время от запроса до ответа API. |
| НФТ-10 | Карточка SKU на загруженных данных открывается за ≤1 с (p95) при нагрузке НФТ-08. | От выбора SKU до отображения карточки. |
| НФТ-11 | Доступность приложения ≥99,9% календарного месяца, включая плановые работы; сбои внешних API учитываются отдельно. | Вход и просмотр загруженных данных. |
| НФТ-12 | Данные и резервные копии шифруются AES-256; соединения под контролем команды используют TLS 1.3. | Настройки, проверка доступа, восстановление копии. |
| НФТ-13 | Кэш названия товара и ссылки на миниатюру — до 10 минут; цена, комиссия и тариф проверяются перед решением отдельно. | Изменение названия или ссылки в источнике и проверка обновления. |
| НФТ-14 | Права на финансы и отправку в Ozon проверяются по ролям; закрепление DBS/FBO не считается ролью. | Проверка по согласованной матрице прав. |
| НФТ-15 | До 10 параллельных пакетов — отклик НФТ-09; при 25–50 — без потерь, с состоянием каждого SKU. При неизвестном результате после таймаута нет автоматической повторной отправки. | Стенд с имитацией ответов Ozon: пакеты 100/1000/4000 SKU, частичный успех, отказ, таймаут и сверка. |

Для чтения внешнего API допускается до трёх попыток с увеличивающейся задержкой и учётом лимитов. После таймаута изменения цены или акции повтор возможен лишь при подтверждённой идемпотентности; иначе сначала проводится сверка SKU.
